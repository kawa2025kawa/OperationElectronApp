# リファクタリング方針: Electron メインプロセスの冗長・中間ロジック削減

## 概要
`electron/` 配下の全ファイルを対象に、過剰な抽象化層、単なる中継ラッパー、重複管理を削減し、コードベースをシンプルかつ見通しよく整理する。
すべての関数名上部に1行の概要コメントを付与し、UTF-8（BOMなし）で保存する。

## 主な削減・整理項目

### 1. 【中間ラッパーの削減】`operationCommandService.ts` の統合・廃止
- 単なる1行中継（`updateOperationJobStatus` -> `updateManualStatus` など）を行っている `operationCommandService.ts` を廃止。
- ターゲット登録や全リセット処理を `statusManager.ts` に集約し、`operationIpc.ts` から直接呼べる構造にする。

### 2. 【二重管理の解消】`statusStore.ts` と `statusManager.ts` の統合
- `statusStore.ts`（単なるインメモリ Map の保持）と `statusManager.ts`（更新・永続化・通知）の境界を解消し、`statusManager.ts` にインメモリ状態を統合。
- `operationQueryService.ts` など外部からの直接 Map 参照を適切なゲッターまたはマネージャー経由に統一。

### 3. 【小分けモジュールの統合】RDP機能の一本化 (`electron/features/rdp/`)
- 30行程度ずつに細分化されている `rdpConnection.ts` と `rdpResolver.ts` を `rdpService.ts` に統合。

### 4. 【デッドコード・未使用ロジックの整理】
- `systemService.ts` 内の未使用定数 `MANUAL_ALIAS_MAP` を削除。
- レンダラー側でクライアントフィルタリングされているため実質未使用となっている `spreadsheetIpc.ts` / `spreadsheetMasterDataManager.ts` の `getFilteredSheetData` を整理。

### 5. 【薄いキャッシュ中継ファイルの整理】`masterData` ストレージ
- `masterDataFileCache.ts` を中継するだけの薄い `jsonMasterStorage.ts` および `spreadsheetMasterStorage.ts` を各マネージャー（`jsonMasterDataManager.ts` / `spreadsheetMasterDataManager.ts`）に直接取り込み、無駄なファイル階層を削減。

### 6. 【関数概要コメントの付与】
- 対象の各関数・ハンドラ上部に1行の概要コメントを追加。
- UTF-8（BOMなし）で保存。
